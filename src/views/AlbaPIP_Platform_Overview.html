Finance Drill-Downs
From red flag to root cause in four clicks.

The drill-down system is the platform's headline feature. Start from a single amber or red metric on the GP Dashboard and drill through four reconciling levels to the individual transactions behind it. Every number at every level ties back to the top-line figure.

Cash Runway Drill — Meridian SaaS (Xero live)
1
Cash Runway Overview — Current cash balance, monthly burn rate, projected runway in months, trend vs prior period. Source: Xero bank accounts + calculated burn.
2
Burn by Category — Breakdown of monthly burn across Payroll, Infrastructure, Sales & Marketing, Operations, and Other. Identifies the dominant cost driver.
3
Accounts Receivable Detail — Total AR, overdue total, aging breakdown (current / 30 days / 60 days / 90+ days). Identifies the cash collection gap vs book revenue.
4
Individual Overdue Invoices — Real invoice numbers, counterparty names, amounts, and days overdue pulled live from Xero. DIISR, Rex Media Group, Port & Philip Freight — the actual debtors behind the number.
Revenue vs Budget Drill
1
Revenue vs Budget — Actual vs budgeted revenue, variance in £ and %, trend line over 12 months.
2
Revenue by Product — Breakdown across product lines showing which products are tracking above or below plan.
3
Revenue by Region — Geographic split with budget vs actual by territory. Identifies where the variance is concentrated.
4
Top Customer Deals — Individual named accounts, contract values, and renewal dates. The customer-level picture behind the regional aggregate.
EBITDA Margin Drill
1
EBITDA Margin — Actual EBITDA, margin %, bridge vs prior period, trend.
2
Margin Bridge — Waterfall showing the contribution of each factor (revenue change, gross margin movement, opex change) to the EBITDA shift.
3
Cost Line Detail — Individual cost lines against budget. Identifies the specific lines driving margin compression.
4
Outstanding Bills — Individual supplier invoices pulled from Xero accounts payable. The actual liabilities behind the cost line.
Why this matters
A traditional portfolio dashboard shows you the number. This platform shows you why the number is what it is — and takes you to the individual invoice or customer deal behind it, without leaving the screen. That's the difference between a reporting tool and an intelligence platform.

Scaling to 100+ integrations
Built for enterprise scale from day one.

The platform's architecture was designed with 100+ integrations in mind, not retrofitted for it. Every integration follows the same pattern — a serverless function, a set of environment variables, and a data mapper. Adding a new system is a predictable, repeatable process.

~2h
Per new integration
A new API-key integration (e.g. a new data provider) takes roughly 2 hours to build, test, and deploy. An OAuth integration (like Xero) takes 4-6 hours including the auth flow.
£0
Infrastructure cost to add
Vercel's serverless model means each new integration adds zero fixed infrastructure cost. Functions only run when called — the platform scales to 100 integrations without a server resize.
1
File per integration
Each integration is a single serverless function file. Xero is 5 files (due to OAuth complexity). Stripe, HubSpot, and every future API-key integration is a single file.
∞
Portfolio companies
The five current companies are seed data. The data layer is built to accept any number of portfolio companies — each connecting their own Xero, Stripe, HubSpot accounts to their own view.
The 100-system architecture
Every integration follows the same four-layer pattern: (1) a serverless API function that authenticates and fetches data, (2) a data mapper that normalises the response into the platform's standard shape, (3) a source tag that marks the data as live, simulated, or stale, and (4) a fallback to representative data if the connection is unavailable. This means any of the 100 integrations can go offline without breaking a single screen. The pattern is proven with six live integrations — the remaining 94 are repetitions of the same process, not new engineering problems.
